# “切换便签栏”快捷键设计

## 目标

为 Nook 增加一个名为“切换便签栏”的便笺内快捷键。用户在便签栏中打开一张便笺后，可以按快捷键直接切换到下一张便笺，连续浏览时不必先关闭当前便笺再点击另一个标签。

## 交互规则

- 默认快捷键为 `⌃Tab`（Control + Tab）。
- 快捷键显示在“设置 → 快捷键 → 在打开的便笺中”，允许用户重新录制或清除。
- 仅当停靠在便签栏中的便笺已经打开且该窗口获得焦点时生效。
- 已拖出便签栏的悬浮便笺不响应此功能。
- 切换顺序使用 `NoteStore.active`，与便签栏的排序一致；归档便笺不参与。
- 当前便笺不是最后一张时打开下一张；位于最后一张时循环到第一张。
- 只有一张活动便笺时不做任何动作。
- 如果当前便笺已经不在活动列表中，则不进行猜测性跳转。
- 切换时关闭当前查找栏，并按下一张便笺的位置重新计算打开高度。

## 技术设计

在现有便笺窗口本地按键监视器中识别新快捷键，保持它与关闭、归档、删除、查找、任务、固定、颜色及字号快捷键相同的作用域。匹配成功后，由 `DeckController` 根据活动便笺列表计算下一项，并在当前面板内直接替换 `expanded` 的便笺 ID。

不采用“先收起再展开”的流程，以免应用失焦、便签栏闪烁或产生多余动画。也不注册 Carbon 全局热键，避免用户在其他应用中按 `⌃Tab` 时被 Nook 截获。

## 设置与文案

- 新增持久化设置 `scCycleDeck`，默认值为 Control + Tab。
- 在快捷键设置模型、初始化、重复快捷键检测和设置行中加入该项。
- 中文名称为“切换便签栏”；英文名称为 “Cycle deck”。
- 欢迎页和关于页不增加快捷键说明，避免信息过载；设置页是完整快捷键清单。

## 数据与保存

编辑器输入仍按现有机制立即更新共享的 `NoteStore`，SQLite 写入继续使用原来的防抖保存。切换功能不修改便笺内容、排序、固定状态或归档状态，也不引入新的数据迁移。

## 验证标准

1. 默认 `⌃Tab` 能在打开的便笺间按便签栏顺序切换。
2. 最后一张能够循环回第一张。
3. 单张便笺、当前 ID 缺失和空列表均安全地不执行切换。
4. 归档便笺不会出现在切换序列中。
5. 自定义或清除快捷键后立即生效，并参与重复快捷键提示。
6. 切换不会收起便签栏、让应用失焦或影响悬浮便笺。
7. 原有快捷键、编辑器测试、持久化测试和 Release 构建继续通过。
